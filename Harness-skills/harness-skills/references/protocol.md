# 调度与运行协议

## 来源与版本

每条来源记录URL、访问日期、发布日期、模型版本、benchmark名称/版本、评测框架、工具权限、effort、上下文和输出预算、采样数及得分。区分厂家报告、独立评测和本项目实测。比较同一模型不同harness，比较同一任务的质量/延迟/修正率/实际成本；不能拿不同日期、不同模型版本的数字拼“公平排名”。API版本变化时更新证据，不硬编码一个永久“最新模型”。

## 三层路由

模型能力决定适合的任务；客户端决定能否真正读写文件/调用工具；固定Python/R或OmicOS内核产生科学计算。三者分别验收。执行者确认产物产生，复审者检查独立错误目标，例如统计单位、泄漏、混杂、来源、因果越界、预期不变量。

适配器必须遵循核实过的协议，Messages、Chat Completions、Responses不能互相推论。地址拼接只有一个版本段；按授权host绑定key并禁止向未知重定向转发。参数支持逐提供方核实；low/high/max不一律默认max。网关接受字段不证明真的执行了该档位。能力状态为unknown/documented/probed/task_verified之一，不能由无报错跳至task_verified。

当前Codex会话不是可凭空调用的HTTP端点；用external角色实际完成工作，记录会话和产物后交其它模型审。Claude Code接Kimi时执行模型family为Kimi；同厂不同型号不算跨family。不同会话审查不保证底层模型来源独立，身份只能按可确认的提供方声明记录。

## 状态、预算与恢复

每模块状态draft → awaiting_review → accepted / needs_revision / blocked。修改后重新审，最多两轮无解则说明依赖与阻断。不把审查者再无限递归审查。预算至少含max_calls、max_output_tokens、max_input_chars；价格可核实才设置金额预算，不能拿官方价替换网关价。CLI/工具内隐含请求也要明确单独记账边界。

每次调用记录route、quota_group、时间、状态、数值usage、耗时与run ID，不保存响应中的凭证回显。失败重试有上限；配额失败按账号组冷却，同组其它模型不能当独立额度。更换模型使用相同经过选择的证据；更换导致审核条件不满足则停止该依赖步骤。

## 独立复审与授权

真实作者session必须可追溯，不能把原稿作者换成协调者来绕过自审。reviewer获得原始任务、必要来源、当前产物以及实际用到的记忆。回执绑定字节SHA256，P0/P1未解决不通过。准备证据包不会自动授权发送：遵守用户已有范围和平台审批；拒绝时不得通过改路径/换协议规避。

每轮模式选择由用户级AGENTS规则或技能提问完成，是操作约定而非后台拦截器。仅Codex不使用第三方模型，但允许必要的普通工具。用户可明确修改默认模式；模式回答与同轮补充不重复追问。
