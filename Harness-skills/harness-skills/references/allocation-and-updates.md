# 分包、复审与可选择更新

## 先适配现有skills

从当前会话技能目录和用户指定项目读取相关skill的名称、范围、路径、版本或hash，仅展开任务需要的SKILL.md。先复用现有流程，不凭关键词加载全部技能，不修改无关skill或共享跨项目记忆。模型、客户端、工具、分析内核分别登记；能用现有确定性脚本完成的转换不增加模型调用。

运行Harness不等于同意更新skill。发现API、benchmark或依赖变化时生成候选差异：保留项、建议修改项、依据、兼容影响、受影响文件及验证结果。让用户选择保持现状、选择具体项或批准全部所列改动。批准绑定具体差异；有新增修改重新展示。用户已明确要求当前这组更新时可完成，不重复确认。未批准不覆盖安装版，也不把候选复制到自动发现目录。失效路线停止调用并说明，不为了维持旧配置发送错误凭证。

批准后备份旧文件，保留用户自定义，测试后仅更新所选路径，报告结果与回退位置。仓库根README仅索引，各skill有独立资源；项目API清单、端点私有配置、密钥、运行回执不进入通用skill目录。新版benchmark只用于建议，不能自行触发升级。

## agent数量

每个详细模块默认四个逻辑字段：primary主执行、primary_fallbacks主执行递补、supplement独立补充执行、reviewer独立复审。递补只在主执行不可用/认证失败/额度冷却/任务失败且有日志时替代主执行；无论主执行成功与否，supplement仍执行自己的范围。补充作者与主执行使用独立session、证据包和输出；不能把补充当备用。reviewer必须排除主执行、实际递补者、补充作者和实质整合者的family/session。

普通模块仍是1主执行+1补充+1复审。大量相互独立材料可先2个分块主执行者，各拥有独立输出路径；每块审查，合并后再审跨块一致性。共享账号并发从1起，只有经验证的限额与预算允许才提高；逻辑worker数量不是HTTP并发数。并发取工具槽位、provider额度、内存和文件所有权允许值的最小值。

关键决策可2个互补复审者，分别审方法和证据，不复制完整长评。所有复审者未参与该产物创作；Harness模式下声明家族与所有贡献作者不同。没有合适审查者保持pending。仅Codex模式按用户选择使用同家族新会话并明确标注，不冒充跨家族。合并产物记录所有分块作者和整合者；实质改写形成新hash重新审。分歧由未参与创作和此前审查者根据证据裁决，不以多数票判真。限制修订轮次，不递归审查复审者。

## 怎样分包才可能节省成本

Codex负责验收边界、必要真实工具执行和整合。将明确代码草案、批量提取、文档综合交给适合的授权路线；难题才升级强推理。Claude既可执行也可审查：常规补丁、文档论证、难调试分别校准其候选型号，不能只固定作终审。大量重复任务优先用户指定的吞吐路线；“Flash/小型号”名称不证明实际网关便宜。真实工具客户端经验证和授权可执行；文本HTTP输出不能冒充命令日志。

每包记录task_id、必要原文引用/hash、输出schema、验收条件、文件所有权、依赖、调用/输入/输出/时间预算。不要复制全聊天或整个仓库给每个worker。复审必须读必要原始证据与当前产物，而非作者摘要。先小型已知答案校准，再扩大批次；不能只抽查一块就声称所有模块复审通过。

分别记录Codex额度、各API实际usage/账单、CLI权益、重试、复审、延迟和修订量。少用Codex不必然降低总费用。按账号组冷却，不借同网关换型号绕限额。不使用重置卡，不自动购买；独立服务只有当前可用且授权时递补。后台续跑必须有真实运行器，不能由配置文字承诺。

## 视觉和证据强度

候选按最新官方模态文档与项目测试选择：批量图片/PDF理解、复杂图表推理、争议复核分别分工。先测合成已知答案图片的文字、轴向、图例和面板，再启用图片路线；文本短测不验证图片透传。只发送授权图片。数值、计数、强度等科学测量来自原始数据和专业分析，不用视觉语言模型猜数替代。

记录实际client/endpoint、账号组、family、model和session。Codex是客户端，GPT/Codex执行模型按openai家族；同厂型号、同模型不同网关不是不同家族。旧family=codex只兼容读取，比较时归一openai。未知家族不能编造。

声明家族不同的网关审查只证明程序性分工，不能证明底层身份独立。关键最终门槛由项目明确指定可信客户端/端点、审查范围及未满足时的pending状态；不要把特定项目的Kimi/Codex配对强加给所有未来项目。若运行器未强制此门槛，应如实注明需要协调者执行，结构校验或文本回执不是最终放行证明。
