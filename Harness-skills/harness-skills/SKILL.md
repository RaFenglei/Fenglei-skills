# Harness-skills

这是可执行的Codex工作流程，不绑定模型型号、网关或课题。调用本技能时读取本项目当前清单，不复用其它项目凭证或旧评测结论。

## 运行模式

每个新用户请求若未选模式，先问“本轮仅用Codex，还是使用Harness？”遵守用户级模式规则；选择回复不是新请求，不循环询问。明确“Harness”或仅调用本技能来设计harness不等于同意把私密资料发往任意API。仅设计/保存请求只完成设计和文件，不自动做收费探测。

仅Codex：当前Codex实际执行，必要时另一独立Codex会话复审，标明同family，禁止调用额外模型API。Harness：按以下流程使用授权API。未回答时仅做本地准备或只读工作，不把超时当同意。

## 重新设计

先读 [分包与可选择更新](references/allocation-and-updates.md)：按实际已安装skills适配，展示具体候选差异，由用户决定保持、部分或全部更新；仅运行不自动覆盖skill。用户已明确授权当前所列更新时直接完成并备份，不重复确认。按任务复杂度配置单执行/复审、分块或专项复审，不能默认每个模块都多agent重读全文。详细角色固定区分 primary 主执行、primary_fallbacks 仅主执行递补、supplement 独立补充执行和 reviewer 独立复审；补充执行不是备用。

1. 确认项目目录、任务产物与验收条件；用 `scripts/manage.py init --project <目录>` 创建不覆盖已有文件的 `.harness` 模板。清单仅填非秘密metadata：提供方、真实model ID、协议、允许host、key环境变量名、账号额度组、上下文/输出限制、实际价格依据、客户端和验证时间。密钥只留项目进程环境或秘密存储。
2. 用户更新API时，读取新清单及授权范围；停止使用失效路线并提出配置变更，按用户批准范围写入，失效对应能力/复审记录并保留旧审计。不能向猜测端点试key。模型、API服务商、Claude Code/Codex等客户端、OmicOS等计算环境分列。
3. 按 [调度协议](references/protocol.md) 查最新官方API规则和原始benchmark，记录版本、日期、harness、effort、预算及来源。只将可比成绩当任务先验；网关同名不等于原厂能力。没有公开分数就写未验证，不编造排名。已有新鲜来源可复用，但API/模型版本变化必须重查。
4. 按模块分配：Codex保留实际设计、代码/测试和整合职责；大量输入可优先用户指定吞吐路线；推理、工程、科学审查按证据分工，不能所有任务都固定某一家首发。每个模块写真实平台、客户端、模型、协议/endpoint、额度组、primary、primary_fallbacks、supplement、reviewer和审查目标；补充执行与主执行使用独立session和证据包。递补后重新排除所有实际作者的family/session。运行 `manage.py check` 校验结构和角色；它不调用API也不证明科学正确。
5. 由另一个agent独立复审新方案。Harness默认要求不同family且不同session；缺第二family则标blocked，不自动降级。仅Codex模式允许同family新会话，不能声称跨family通过。明确区分本地agent审查、离线测试、真实短测、完整任务验收。

## 执行

按 [调度协议](references/protocol.md) 准备当前客户端/协议适配。使用现有经过审查的runner、官方SDK或Codex工具；没有兼容适配器时先实现与离线测试，不假装本技能自带所有API客户端。收到执行授权且未被平台审批阻断后，先做预算内短探测，再按冻结路由执行。只发送批准范围内的证据；不把整个项目目录、密钥或样本原始矩阵默认发给模型。

每一步保存输入/代码/环境/产物hash与真实日志；补充执行先独立产出，再由主执行整合；实质整合者加入作者集合。reviewer用新会话审同一证据和产物，不继承作者对话。判定pass/revise/block与问题级别；P0/P1、无效JSON、截断、未执行均不能pass。产物变化使旧通过失效。`manage.py receipt-check`只检查回执结构/hash/角色，不创建或伪造通过。

限额按实际账号组冷却，换同网关型号不能绕限额；有限重试，每次尝试计预算。401/403停止盲试，429尊重Retry-After，超时若可能已计费则记ambiguous，不无限重放。同能力递补不能降低审核条件；缺route则blocked。实际命令执行与模型文字建议分开记录。需要OmicOS时先只读确认内核/CLI，避免复审继承有状态分析会话。

## 可选记忆与交付

用户要求额度不足时不使用重置卡、不自动购买；只用已授权的Kimi或其它可用API递补。若API在其它对话，先核对相关对话的项目范围、端点和授权，不全历史搜集密钥，不将凭证复制进技能或仓库，不绕过平台审批。若用户之后明确禁止外部模型，以最新选择为准。

默认不推断跨项目授权。用户可选off/project/cohort：项目内仅共享已审方法和结论，样本结果用sample_id隔离，cohort需显式指定。只有绑定当前有效回执的精确文本进入共享记忆；撤回、删除、hash变化后停用。参考 [模板字段](references/schema.md)。

交付路由及理由、benchmark来源、运行/复审记录、未验证或blocked项、可重跑命令。保存本地项目快照；发布技能只包含通用模板和代码，排除真实配置、凭证、内部地址、结果、日志和秘密存储。用户只要求设计时到此完成设计，不追问批准额外收费执行。
